# Capture All

A Chrome extension that records network logs, user interactions, and DOM element snapshots — and exports both JSON and a fully self-contained interactive HTML Timeline for instant, human-readable visualization.

- **Network Logging**: via Chrome Debugger API
- **Console Errors**: `console.error`, failed asserts and uncaught exceptions, with file and line
- **User Interactions**: clicks, scrolls, drags, inputs, key events
- **Element Snapshots**: DOM metadata, selectors, positions, visibility
- **Dual Export**: JSON + interactive HTML timeline (autogenerated)
- **Playback**: play/pause/reset, variable speed, live “Current Event”
- **Privacy**: all data stays local

## Highlights

- **One-click Export → One `.zip`**
  - `capture_all_[timestamp].zip` containing a `capture_all_[timestamp]/` folder with
    `timeline.html`, `logs.json` and (video mode) `video.webm`
- **Parallel Timeline Tracks**
  - Network Requests
  - User Interactions
  - Element Snapshots
- **Playback Controls**
  - Play / Pause / Reset
  - 0.5x, 1x, 2x, 5x, 10x speeds
  - Live “Current Event” updates as the cursor moves
- **Compact, Scrollable Timeline**
  - Smaller event cards
  - Horizontal scrolling for long sessions
  - Tooltips for full event titles

## Installation

1. Clone or download this repository.
2. Open Chrome and go to `chrome://extensions/`.
3. Toggle on “Developer mode”.
4. Click “Load unpacked” and select this folder.

## File Structure

- `manifest.json`
  - Declares permissions: `activeTab`, `storage`, `tabs`, `scripting`, `debugger`, `downloads`
  - Registers background service worker: `background.js`
  - Popup: `popup.html`, `popup.js`
- `background.js`
  - Attaches Chrome Debugger
  - Captures network events: requestWillBeSent, responseReceived, loadingFinished, loadingFailed
  - Receives interaction logs from content script
  - Coordinates exports (JSON + HTML)
  - Generates the self-contained timeline HTML
- `content.js`
  - Tracks interactions: click, scroll, drag, input, keydown, mousemove (where applicable)
  - Captures element snapshots on demand
  - Sends `logInteraction` messages to background
- `popup.html` / `popup.js`
  - UI for Start/Stop recording
  - Capture Elements
  - Export Logs (downloads one .zip)
  - Clear Logs
  - Real-time stats panel

## Permissions

- `activeTab`, `tabs`, `scripting`: inject and communicate with pages
- `storage`: persist interactions and element snapshots
- `debugger`: network logging via Chrome Debugger API
- `downloads`: save the export .zip
- `host_permissions`: `<all_urls>` for broad page access

## Usage

1. Open the popup.
2. Click “Start Recording”.
3. Interact with the page (click, scroll, drag, type, etc.).
4. Optionally click “Capture Elements” to snapshot visible interactive elements.
5. Click “Stop Recording”.
6. Click “Export Logs” and choose where to save the `.zip`.
   - Unzip it and open `timeline.html` in any browser (keep it next to `video.webm`).

**Starting from a New Tab or another Chrome page.** Chrome doesn't let any extension record its own pages
(New Tab, Settings, History, Extensions, the Web Store). There the button reads **Start on next website**:
press it and the tab waits (badge `WAIT`).
- Logs only: recording starts by itself when the tab opens a website. Only that page's own HTML request is
  missed, because it goes out before Chrome lets the extension attach.
- Video + logs: Chrome allows tab video only after you click the extension on the page itself. When the website
  has loaded, the badge shows `▶`; click the Capture All icon and recording starts straight away.
- Press **Cancel** to stop waiting. Closing the tab also cancels.

**Local files** (`file://`): turn on "Allow access to file URLs" for Capture All. The popup shows an
**Open file access settings** button when it's off.

## Exported Files

One `capture_all_[timestamp].zip` with a `capture_all_[timestamp]/` folder inside:

- `logs.json`
  - Raw data for programmatic analysis
- `video.webm` (video mode only)
- `timeline.html`
  - Timeline viewer (no external dependencies; in video mode it plays `video.webm` from the same folder)
  - Includes:
    - Parallel tracks (Network / Interactions / Snapshots)
    - Compact, scrollable event cards
    - Playback cursor with Play/Pause/Reset + speed
    - Live “Current Event” panel updating as the cursor moves
    - Click an event for detailed metadata panel

## Timeline Viewer (HTML) – Key Features

**Session replay** (Video + logs mode)
- Video with click markers that name the clicked element, a scrubber marked with clicks, snapshots and page changes, and a hover tooltip
- Network tab: filter by type or errors, hide CORS preflight, search; open a request for query parameters, headers, bodies, Copy URL and Copy as cURL
- Interactions tab: rows read as actions; scroll bursts and typing in one field collapse into one row; page changes get a divider; selectors and XPath are copyable
- Snapshots tab: open a snapshot to outline every visible link, button and field on the video, search them, and copy selectors or the whole snapshot as JSON
- Follow keeps the current row in view while playing; keys: Space, ←/→, `/` filter, `F` follow, Enter opens a row, Esc hides outlines

**Logs timeline** (Logs only mode)
- Event pills per track, a playback cursor and a live "Now" panel
- Click a pill for the same detail views as the replay (cURL, headers, snapshot map and element list)

Both are single offline files, work in light and dark, and respect "reduce motion".

## How It Works (Under the Hood)

- `background.js`
  - `startRecording(tabId)`
    - `chrome.debugger.attach({ tabId }, '1.3')`
    - `Network.enable`, `Runtime.enable`
  - Network event handlers:
    - `Network.requestWillBeSent` → capture method, URL, headers, postData
    - `Network.responseReceived` → status, statusText, headers
    - `Network.loadingFinished`/`loadingFailed` → completion/failure
  - Interaction logging:
    - Receives `logInteraction` from `content.js` and stores in `chrome.storage.local`
  - Export:
    - Aggregates network + interactions + snapshots
    - Builds one .zip (JSON + HTML timeline + video) in the offscreen document
- `content.js`
  - Sends user interactions to background via `logInteraction`
  - Provides `captureElements` snapshot on demand
- `popup.js`
  - Sends control messages: start/stop/capture/export/clear
  - Displays counts (network, interactions, snapshots)

## Usage Tips

- Start recording before interacting with the page
- Use “Capture Elements” after the page stabilizes to snapshot meaningful elements
- Export after stopping to ensure timeline includes all events
- Share the .zip with teammates — no setup required

## Troubleshooting

- Recording won’t start
  - Another debugger may be attached. Refresh the page and try again.
- "Chrome blocks recording its own pages"
  - Expected on New Tab, Settings, the Web Store and other Chrome pages. Use **Start on next website** (see Usage).
- Missing interaction events
  - Content script injection may have failed on restricted pages (e.g., chrome://)
- Network count not updating
  - Ensure popup uses `response.networkLogsCount`
- Exports don’t download
  - Ensure `downloads` permission is present and allowed in Chrome
- HTML looks empty
  - Check that there are events in the JSON; re-export after recording some actions

## Privacy

- All data is stored locally in your browser
- Nothing is sent to external servers
- **Skip in export** (popup): switches that decide what the exported zip leaves out. All start on.
  - *Typed text*: field values (including the `value` attribute that frameworks like React fill with what
    you type, passwords too), and the text of textareas and rich-text editors. Button labels and checkbox or
    radio values are kept. Typing still shows as a character count.
  - *Private areas*: text and values inside `.rr-mask`, `.rr-block` or `[data-private]` elements.
  - *Logins and keys*: auth and cookie headers, and URL parameters, JSON keys and form fields named like a token,
    key, session, password or signature, in requests, page URLs and links. They become `REDACTED`.
  - *Request and response bodies*: POST data and response bodies. Their size is kept.
  - The switches apply at export. What was captured stays in browser storage until you export or press Clear.
    `logs.json` records which switches were on (`exportSkip`) and how many values were left out (`redacted`).
- Matching is by name, so personal data inside pages or kept bodies isn't detected, and video can't be redacted.
  Details, and notes for IT administrators: [PRIVACY.md](PRIVACY.md).
